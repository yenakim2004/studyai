# 배포 요청부터 AI 연결까지 진행하기

Sites를 다루는 에이전트가 사용하는 절차입니다. 사용자가 `@Sites`로 StudyAI 배포나 AI 연결 설정을 요청하면 서버 준비를 맡고, 직접 해야 하는 단계만 하나씩 안내하세요. 현재 ChatGPT 플랜 연결은 실험 기능이며 실제 Sites 지원은 확인되지 않았습니다.

## 1. 사이트와 실행 환경 확인

새 배포라면 사용자 전용 비공개 사이트를 만드세요. 기존 사이트를 받았다면 Sites 도구로 해당 사이트와 접근 범위를 확인하세요. 새 프로젝트로 대체하지 마세요.

사용 가능한 Sites 스킬과 도구를 먼저 확인하세요. [서버 배포 절차](SITES.md#개인-서버-배포)에 따라 소스를 준비합니다. 저장소의 `packageManager`에 고정된 pnpm과 Node.js 22 이상을 사용하세요.

로그인 도구를 사용자의 브라우저와 같은 컴퓨터에서 실행할 수 있는지도 확인하세요. 클라우드 실행기의 `127.0.0.1`은 사용자 컴퓨터가 아닙니다. 같은 컴퓨터에서 실행할 수 없다면 서버 준비까지 마친 후 로컬 도구 실행 안내로 이어가세요.

## 2. AI 서버 설정 준비

에이전트가 다음 작업을 수행하세요. 사용자에게 환경 변수 값을 직접 작성하라고 요청하지 마세요.

1. 서버 빌드와 `DB` D1 바인딩을 구성하세요. 기존 Drizzle 마이그레이션을 포함하세요.
2. `STUDYAI_SITE_ORIGIN`을 실제 사이트의 HTTPS origin으로 설정하세요.
3. 새 설치에만 `CHATGPT_SEAL_KEY`를 생성해 Sites의 런타임 secret으로 저장하세요. 이미 설정되어 있다면 그대로 유지하세요. 값을 출력하지 마세요.
4. 연결 도구가 포함된 `build:sites-server`를 빌드하세요. `node scripts/verify-sites-build.mjs`로 배포 산출물을 검사하세요.
5. 공식 Sites 절차로 같은 소스를 동기화하고 패키징해 배포하세요. 사이트가 배포 전부터 존재했다면 접근 범위를 유지하세요.
6. 배포 결과를 확인하고 `/settings` 링크를 제공하세요. 환경 설정 변경은 새 배포에 적용하세요.

기존 `.studyai-local/`이나 T3, Codex의 인증 파일을 복사하지 마세요. 설정을 확인하려고 암호화 키를 교체하거나 D1의 계정 행을 읽어 출력하지 마세요.

## 3. 사용자에게 연결 안내

첫 안내는 짧게 하세요.

> 사이트와 AI 서버 준비가 끝났습니다. 이제 본인 ChatGPT 계정을 연결합니다. 로그인과 동의는 직접 진행하고, 제가 실행할 수 있는 도구 준비와 실행은 맡겠습니다.

설정 화면에 이미 연결된 계정이 있다면 재연결을 시작하지 마세요. 연결 상태를 확인하고 필요한 모델 선택과 첫 질문 단계로 이동하세요.

현재 파일 연결에서는 다음 순서로 진행하세요.

1. 로그인한 사용자가 본인 사이트 설정에서 **ChatGPT 연결 요청 파일 받기**를 누르게 안내하세요. 브라우저 조작을 허용받았다면 해당 작업을 도울 수 있습니다. 허용받지 않았다면 직접 조작하지 마세요.
2. 요청 파일의 위치를 확인하세요. 내용 전체를 채팅에 붙여 넣게 하지 마세요. 요청은 10분 후 만료되므로 미리 만들지 마세요.
3. 같은 컴퓨터의 에이전트는 검토한 소스의 `pnpm cli:build` 결과인 `dist-cli/studyai-connect.mjs`를 실행하세요. 사용자가 직접 도구를 내려받거나 터미널 명령을 작성하게 할 필요가 없습니다.

```bash
node dist-cli/studyai-connect.mjs '/실제/요청 파일.json' --output '/실제/새 연결 결과.json'
```

4. 도구가 수신 준비를 마친 뒤 출력한 OpenAI 로그인 URL을 사용자에게 제공하세요. 사용자가 로그인과 플랜 사용 동의를 직접 마치도록 기다리세요. 비밀번호나 인증 코드를 채팅에 요청하지 마세요.
5. 성공하면 암호화된 결과 파일의 경로를 알려주세요. 로그인한 사용자가 같은 사이트의 **암호화된 연결 결과 파일**에 올리게 안내하세요. 허용된 브라우저 도구로 업로드할 수 있다면 대신 처리하세요.
6. 이 작업에서 실행한 연결 도구가 종료되었는지 확인하세요. 파일 삭제는 사용자 요청 없이 수행하지 마세요.

사용자 브라우저에 접근할 수 없는 환경에서는 요청 파일 받기와 결과 파일 올리기가 남습니다. 에이전트가 모두 자동으로 끝낼 수 있다고 안내하지 마세요. Sites 서비스 접근 토큰에는 방문자 신원이 없습니다. 사용자 식별 헤더를 만들어 보내거나 사이트의 로그인 검사를 제거하지 마세요.

## 4. 실제 연결 확인

설정에 계정이 표시되는 것과 AI가 실제로 답하는 것을 구분하세요.

1. 로그인한 사이트에서 모델 목록을 조회하고 사용할 모델을 고르세요.
2. 사용자가 고른 자료와 질문으로 첫 튜터 답변을 확인하세요. 전송할 자료와 질문을 사용자에게 보여주세요.
3. 실패하면 실제 오류에 따라 복구하세요. `chatGptPlanConnected` 같은 표시 값을 강제로 바꾸지 마세요. 연결 거부를 새로운 로그인으로 반복하지 마세요.

결과는 `서버 준비 완료`, `계정 연결 확인`, `모델 조회 확인`, `첫 답변 확인`으로 나누어 보고하세요. 확인하지 못한 항목은 미확인으로 남기세요. 토큰 만료 후 갱신은 별도 검증이며 첫 답변 성공만으로 완료 처리하지 마세요.

## 5. 나중에 설정을 다시 요청하기

설정 화면의 **AI 설정 요청문 복사**에는 현재 사이트 주소가 들어갑니다. 사용자는 그 요청문을 Sites를 사용할 수 있는 대화에 붙여 넣을 수 있습니다. 기존 사이트와 연결을 먼저 확인하고 필요한 작업부터 이어가세요.

웹사이트용 승인된 OAuth 클라이언트가 제공되면 공식 계약을 확인한 후 연결 방식을 변경하세요. 공개된 로컬 인증 흐름의 콜백 주소를 임의의 HTTPS 주소로 바꾸지 마세요.
