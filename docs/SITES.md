# Sites 배포 안내

StudyAI는 Sites에 **정적 학습 앱**으로 올립니다. PPTX·PDF 가져오기, 검색, 노트, 플래시카드, 모의시험은 방문자 브라우저에서 실행됩니다. 로컬 ChatGPT 구독 연결은 배포 대상이 아닙니다.

이 문서는 저장소를 Sites로 가져올 때의 설정입니다. 빌드 성공이나 로컬 브라우저 테스트 통과만으로 실제 Sites 배포가 완료된 것은 아닙니다. 게시 완료는 Sites가 반환하는 배포 결과와 URL로 확인합니다.

## 배포 순서

1. 이 저장소를 열고 Node.js 22 이상에서 `pnpm install --frozen-lockfile`을 실행합니다. pnpm 버전은 `package.json`의 `packageManager`를 따릅니다.
2. `pnpm build:sites`로 빌드합니다. 출력은 `dist/`입니다. `pnpm build:demo`는 GitHub Pages 체험판용이므로 Sites 배포에 사용하지 않습니다.
3. Sites 도구로 새 프로젝트를 만들거나 지정된 기존 프로젝트를 엽니다. 새 사이트의 접근 범위는 비공개로 시작하고, 다른 사람에게 공개할지는 별도로 정합니다.
4. Sites가 발급한 실제 프로젝트 ID로 `.openai/hosting.json`을 만듭니다. 기존 사이트를 수정할 때는 기존 ID와 접근 범위를 보존합니다.
5. 소스를 Sites 저장소와 동기화하고, 해당 커밋에 대응하는 `dist/`를 공식 Sites 소스·패키징 도구로 저장하고 배포합니다. 반환된 배포 ID와 버전을 재사용하며 중복 프로젝트를 만들지 않습니다.
6. 배포 결과가 성공인지 확인하고 실제 URL을 안내합니다. 실패했다면 게시 완료로 안내하지 말고 오류를 확인합니다.

배포 설정의 형태는 다음과 같습니다. `<실제 프로젝트 ID>`는 설명용이며 이 문자열을 그대로 사용하지 않습니다. 다른 사용자도 저장소를 가져와 새 사이트를 만들 수 있도록 이 저장소에는 특정 사이트의 ID를 미리 넣지 않습니다.

```json
{
  "project_id": "<실제 프로젝트 ID>",
  "static": { "directory": "dist" }
}
```

Sites의 빌드 도우미가 기본 `build` 스크립트만 실행하는 경우, **배포용 체크아웃에서만** `build`를 `pnpm build:sites`로 지정합니다. 또는 `build:sites`를 먼저 성공시킨 뒤 같은 소스를 다시 바꾸지 않고 패키징합니다. 로컬 앱용 저장소의 기본 `build`는 변경하지 않습니다.

D1·R2 바인딩과 서버 Worker는 필요하지 않습니다. `wrangler.jsonc`와 `worker/`는 로컬 AI 실행용이므로 Sites의 서버 진입점으로 지정하지 마세요. `.studyai-local/`, `.env`, `.dev.vars`, 실제 강의, 백업 ZIP, 테스트 결과는 배포에 포함하지 않습니다.

## 배포 빌드가 바꾸는 것

| 항목 | Sites 빌드 |
|---|---|
| 주소 | 루트 `/`, 정적 출력 `dist/` |
| AI 코드 | 통신하지 않는 대체 모듈을 사용해 `/api/status` 조회와 로그인 요청을 없앰 |
| 데이터 | 방문자의 IndexedDB에 저장. 사용자끼리 자료를 공유하지 않음 |
| 가상 예시 | 기본 앱에는 예제 과목과 체험판 배너를 넣지 않음 |
| PDF | Worker, 문자 맵, 글꼴과 WASM 디코더를 같은 사이트의 자산으로 포함. CDN을 호출하지 않음 |
| 보안 정책 | 문서의 스크립트보다 먼저 CSP 메타 태그를 삽입하고 `_headers`도 출력 |
| 깊은 주소 | `404.html`에 앱을 복사. 호스트의 SPA 라우팅 또는 fallback 설정은 배포 후 확인 |

메타 CSP는 `frame-ancestors` 같은 응답 헤더 전용 정책을 적용할 수 없습니다. `_headers`가 실제 Sites 호스트에서 처리되는지는 게시 후 응답 헤더로 확인해야 합니다. 메타 CSP 자체와 로컬 PDF 디코더는 헤더 없는 정적 미리보기에서도 검사합니다.

## 설치·배포 후 확인

로컬에서 다음을 실행합니다. 브라우저 검사에는 Chrome이 필요합니다.

```bash
pnpm build:sites
pnpm test:e2e:sites
```

게시 후에는 실제 배포 주소에서 다음을 확인합니다.

- 루트와 `/settings`를 직접 열고 새로 고쳐도 한국어 화면이 나옵니다.
- PPTX와 글이 있는 PDF를 넣고 페이지 보기, 검색, 출처 이동이 됩니다.
- 스캔 PDF는 빈 화면이 아닌 페이지 그림으로 보이고 글이 없다고 안내합니다.
- 사이드바를 접었다가 새로 고쳐도 선택을 기억하며 휴대폰 메뉴가 열리고 닫힙니다.
- 설정에는 로컬 전용 AI 안내가 나오고 OpenAI 로그인이나 `/api/` 요청이 없습니다.
- 노트나 카드를 저장한 뒤 새로 고쳐도 남아 있습니다. 다른 브라우저의 자료실은 비어 있습니다.

## 로그인과 구독의 차이

Sites의 접근 정책은 누가 사이트를 방문할 수 있는지 정합니다. 이것이 각 방문자의 ChatGPT 플랜을 StudyAI 튜터에 연결하는 절차를 대신하지는 않습니다. 현재 구현은 `127.0.0.1` 콜백과 로컬 계정 저장소를 사용합니다. 이 흐름을 원격 사이트에서 동작한다고 안내하지 않습니다.

호스팅된 AI까지 추가하려면 지원되는 별도 인증·추론 방식, 사용자별 권한·비밀 저장, 비용 정책을 설계하고 검증해야 합니다. 현재 배포에는 서버 API 키나 운영자의 ChatGPT 토큰을 넣지 않습니다.

공식 제품 안내는 [OpenAI Sites 문서](https://learn.chatgpt.com/docs/sites), 사용 흐름은 [내부 앱 구축·배포 안내](https://learn.chatgpt.com/use-cases/build-and-deploy-internal-apps)를 참고하세요. 배포 매니페스트와 패키징 절차는 설치된 공식 Sites 플러그인의 계약을 기준으로 작성했습니다. 확인 날짜는 2026-11-12입니다.
