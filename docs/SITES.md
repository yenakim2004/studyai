# 내 비공개 Sites에 배포하기

한 사용자당 하나의 비공개 StudyAI 사이트를 배포합니다. 사이트 접근은 Sites 로그인이 관리하고, 튜터 사용 권한은 별도의 ChatGPT 로그인으로 연결합니다. 방문자 여러 명이 하나의 ChatGPT 계정을 공유하는 서비스가 아닙니다.

## 개인 서버 배포

Node.js 22 이상과 저장소에 고정된 pnpm 11.28.11을 사용합니다.

```bash
npx --yes pnpm@11.28.11 install --frozen-lockfile
npx --yes pnpm@11.28.11 build:sites-server
```

1. 공식 Sites 도구로 새 비공개 프로젝트를 만듭니다. 기존 사이트를 수정한다면 프로젝트 ID와 접근 범위를 그대로 사용합니다.
2. 그 프로젝트의 실제 ID로 `.openai/hosting.json`을 만듭니다. 저장소에는 특정 사용자의 ID를 넣지 않습니다.
3. Sites의 서버 환경 설정에 `STUDYAI_SITE_ORIGIN`을 실제 HTTPS 사이트 주소로 지정합니다. 끝의 `/`를 빼고 경로나 쿼리를 넣지 않습니다.
4. 암호학적 난수 32바이트를 base64url로 인코딩한 새 `CHATGPT_SEAL_KEY`를 생성해 Sites의 **secret**으로 저장합니다. 기존 로컬 키나 토큰을 복사하지 않습니다. 값을 소스, 터미널 로그, 채팅에 남기지 않습니다. 재배포 때 같은 키를 유지합니다.
5. 위 명령으로 빌드한 정확한 소스를 공식 Sites 소스 도우미로 커밋·동기화·패키징하고 비공개로 배포합니다. 환경 설정 변경도 새 배포 후 적용됩니다.
6. Sites가 반환하는 배포 결과가 성공인지 확인합니다. 게시 URL의 `/settings`에서 연결 안내가 나와야 합니다.

```json
{
  "project_id": "<Sites가 발급한 실제 프로젝트 ID>",
  "d1": "DB",
  "r2": null
}
```

서버 배포에서는 `static`을 넣지 않습니다. `vite.sites.config.ts`와 `wrangler.sites.jsonc`가 `dist/server/index.js`, `dist/client/`를 생성합니다. `.openai/hosting.json`이 있으면 빌드가 `dist/.openai/`에 복사하며, 생성된 Drizzle 마이그레이션도 함께 넣습니다. 기본 `wrangler.jsonc`는 로컬 Durable Object용이므로 Sites 배포에 사용하지 않습니다.

배포 도우미가 `build`만 실행한다면 배포용 체크아웃에서만 그 명령을 `pnpm build:sites-server`로 지정합니다. 소스 저장소의 로컬용 기본 `build`는 유지합니다. 이미 같은 소스로 빌드를 마쳤다면 패키징 때 반복 실행하지 않습니다.

빌드 후 `node scripts/verify-sites-build.mjs`로 실제 workerd에서 서버 시작·D1·연결 요청 생성을 확인합니다. `pnpm test:e2e:sites-server`는 설치된 Chrome으로 파일 연결 화면을 검사합니다. 이 검사는 외부 로그인 대신 가짜 발급자를 사용합니다.

D1의 `chatgpt_account` 한 행에 사이트 소유자, 고정 호스트 ID, 암호화된 계정 정보, 연결 요청, 갱신 상태를 저장합니다. `installation_checks`는 초기 서버 검사에 사용한 마이그레이션입니다. 적용된 SQL과 메타데이터는 수정하지 않고, 스키마 변경 후 `pnpm db:generate`로 다음 마이그레이션을 생성합니다. R2는 사용하지 않습니다.

## 내 ChatGPT 플랜 연결

1. 사이트의 **설정과 백업 → AI 학습 도우미**에서 **ChatGPT 연결 요청 파일 받기**를 누릅니다.
2. 같은 화면에서 **연결 도구 내려받기**를 누르고 요청 파일과 같은 폴더에 저장합니다.
3. 그 폴더의 터미널에서 다음을 실행합니다. 요청 파일 이름은 실제 이름으로 바꿉니다.

```bash
node studyai-connect.mjs studyai-pairing-XXXXXXXX.json
```

4. 도구가 보여 준 OpenAI 주소를 같은 컴퓨터의 브라우저에서 열고 로그인합니다. 도구는 먼저 `127.0.0.1` 콜백을 수신할 준비를 합니다.
5. 도구가 만든 `studyai-connection-…json` 파일을 같은 사이트의 **암호화된 연결 결과 파일**에 올립니다. 요청은 생성 후 10분 동안 유효하며 한 번만 사용합니다.
6. 계정과 모델 목록을 확인하고 AI 튜터에서 질문합니다. 이후에는 로컬 도구를 종료해도 사이트가 인증 갱신을 담당합니다.

요청 파일은 반드시 본인의 사이트에서 직접 내려받으세요. 다른 사람이 만든 요청 파일로 로그인하면 그 사람에게 연결 권한이 전달될 수 있습니다. 연결 결과는 암호화되어 있으며 요청을 만든 사이트만 해독할 수 있습니다. 원문 토큰은 브라우저 저장소나 파일에 기록하지 않습니다. 업로드를 마친 파일은 삭제해도 됩니다.

최초 연결이 성공한 Sites 사용자에게 계정 소유권이 고정됩니다. 다른 사용자는 AI 경로에 접근할 수 없습니다. **저장된 계정 정보 지우기**는 ChatGPT 등록을 지우지만 사이트 소유권을 다른 방문자에게 넘기지 않습니다.

## 검증 범위와 한계

이 기능은 실험 단계입니다. 실제 Sites의 사용자 식별·위조 헤더 교체·D1·마이그레이션·정적 파일·서버 비밀 전달은 검사했고, 로그인 도구와 암호화 파일·API 흐름은 가짜 OpenAI 발급자와 실제 로컬 D1에서 검사했습니다. 이것이 실제 OpenAI의 연결 승인이나 Sites 지원을 증명하지는 않습니다.

실제 계정에서는 다음을 각각 확인해야 합니다.

- 연결 파일 설치가 성공하는지
- 사이트 서버가 모델 목록을 받는지
- 튜터가 첫 답변을 받는지
- 액세스 토큰 만료 후 사이트에서 갱신되는지

갱신 응답이 유실되면 같은 갱신 토큰을 다시 보내지 않습니다. 기존 액세스 토큰이 남아 있는 동안은 사용할 수 있지만 만료 후에는 다시 연결해야 합니다. 서버 간 요청이 이미 실행 중이면 연결 해제 후에도 그 요청 하나는 제한 시간까지 진행될 수 있습니다. 두 개 동시 요청 제한은 Worker 인스턴스별 제한이며 전역 제한이 아닙니다.

Sites 사용자 식별 헤더를 신뢰하는 서버이므로 임의의 공개 Worker 주소로 직접 노출하지 마세요. 사이트 운영자는 서버 코드와 비밀 설정을 관리하므로 본인 소유의 비공개 사이트에만 연결하세요. 강의 자료는 주소별 브라우저 저장소에 남으며 기기 간 동기화되지 않습니다.

OpenAI의 [개인 VM 연결 안내](https://developers.openai.com/siwc/token-sharing-open-source/self-hosted-vms.md)는 로컬 로그인과 원격 서버로의 안전한 전달, 서버의 갱신을 설명합니다. 이 구현은 사이트의 고정 호스트 ID를 첫 로그인부터 사용합니다. 이는 문서 해석에 따른 선택이며 Sites에 대한 명시적 지원 확인은 아닙니다.

## AI 없는 정적 배포

`pnpm build:sites`는 AI 통신 코드를 제외한 정적 앱을 `dist/`에 만듭니다. PPTX·PDF 보기, 검색, 노트, 카드, 모의시험, 백업은 동작합니다. 이때 매니페스트는 `project_id`와 `"static": { "directory": "dist" }`를 사용하며 D1이나 비밀 설정은 필요하지 않습니다. `pnpm preview:sites`와 `pnpm test:e2e:sites`로 확인할 수 있습니다.

어느 방식이든 `.studyai-local/`, `.env`, `.dev.vars`, 실제 강의, 백업 ZIP과 테스트 결과를 배포에 포함하지 않습니다. 서버 비밀 설정은 Sites에만 저장합니다.
