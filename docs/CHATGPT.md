# 내 ChatGPT 플랜으로 AI 튜터 쓰기 (내 컴퓨터에서만)

StudyAI의 AI 기능(튜터, 문제 생성, 채점 도우미, 채점 기준 점검)은 모두 내 ChatGPT 구독으로 답합니다. 다른 AI 엔진은 없습니다. 내 컴퓨터에서 `pnpm local`로 실행했을 때만 동작하며, 인터넷에 올린 사본에는 AI가 없습니다.

## 실행하기

```bash
pnpm install
pnpm local
```

`pnpm local`은 `node scripts/local.mjs`를 실행합니다. git 없이 압축 파일로 받은 폴더에서도 됩니다.

1. 실행기가 `StudyAI가 실행 중입니다: http://127.0.0.1:8790`을 출력합니다.
2. 그 주소를 엽니다. `localhost`가 아니라 `127.0.0.1`을 쓰세요.
3. 설정 → AI에서 **ChatGPT로 계속하기**를 누르고, OpenAI에서 StudyAI를 허용한 뒤, 이어지는 페이지의 **StudyAI 설정으로 돌아가기**를 누릅니다.
4. 목록에서 모델을 고릅니다. 목록은 OpenAI가 내 계정에 알려 준 그대로이며, 앱에 박아 둔 모델은 없습니다. 고르지 않으면 목록의 첫 모델을 씁니다.

따로 만들거나 입력하는 키, StudyAI 로그인은 없습니다. 끄려면 Ctrl+C를 누르거나 터미널 창을 닫으세요. 다음 `pnpm local`은 같은 봉인 키, 상태, 연결을 그대로 씁니다.

포트는 8790으로 고정입니다. 사용 중이면 실행기는 다른 포트를 고르지 않고 멈춥니다. 포트가 다르면 브라우저 입장에서 다른 사이트이고, IndexedDB의 내 자료는 사이트별로 따로 있기 때문입니다. 일부러 다른 포트를 쓰려면 `STUDYAI_PORT=<n>`을 지정하세요. 그 포트에는 별도의 자료실이 생깁니다. 같은 폴더로 실행기를 두 개 띄우는 것은 거절합니다. 두 Worker가 같은 회전 토큰을 동시에 새로 고치지 않게 하기 위해서입니다. 남아 있는 잠금 파일은 자동으로 빼앗지 않습니다. 반쯤 쓰인 잠금이나 남아 있는 Worker가 아직 실행 중인 서버의 것일 수 있습니다. Ctrl+C, 종료 신호, 터미널 창 닫기는 잠금을 풉니다. 강제 종료나 전원 차단 뒤라면 그 폴더를 쓰는 서버가 모두 꺼졌는지 확인하고 `.studyai-local/launcher.lock`만 지운 뒤 다시 실행하세요.

실행기는 저장소의 `.dev.vars`를 읽지 않습니다.

## 무엇을 어디에 저장하나

모두 프로젝트 폴더의 `.studyai-local/`에 있으며 git이 무시합니다. 폴더 권한은 0700입니다. 실행기가 직접 쓰는 비밀 파일은 0600이고, `state/`와 `logs/` 안의 파일은 Wrangler가 관리합니다.

| 파일 | 내용 |
| --- | --- |
| `secrets.json` | ChatGPT 봉인 키. 처음 한 번 만들고 다시 쓰지 않습니다. 이전 버전이 만든 파일이면 지금은 쓰지 않는 값이 더 들어 있을 수 있는데, 실행기는 봉인 키만 읽고 파일은 건드리지 않습니다. |
| `dev.vars` | `wrangler dev --env-file`로 Worker에 넘기는 값: 루프백 주소와 봉인 키. 실행할 때마다 다시 씁니다. 비밀 값은 명령줄에 나타나지 않습니다. |
| `state/` | Durable Object의 SQLite 저장소. 아래의 ChatGPT 계정이 여기 있습니다. |

이전 버전이 남긴 `owner-key.txt`가 있다면 더는 쓰이지 않습니다. 지워도 됩니다.

ChatGPT 계정 (`worker/src/chatgpt.ts`만 씁니다):

- **그대로 저장.** 발급된 클라이언트 ID(`oaiapp_…`), 계정의 `sub`와 이메일, "플랜 사용 꺼짐" 표시, 고른 모델, 모델 목록, 마지막 알림.
- **AES-256-GCM으로 봉인.** 접근 토큰, 갱신 토큰, 만료 시각. 봉인한 값마다 그 행의 리비전에 묶여 있어 다른 행으로 옮기면 열리지 않습니다.
- **저장하지 않음.** ID 토큰. 로그인 때 한 번 검증하고 버리므로 `id_token_hint`도 보내지 않습니다.
- **로그인하는 10분 동안만.** `state`의 해시, nonce와 PKCE 검증값(봉인).

브라우저는 이 비밀 값을 하나도 받지 않습니다. 어떤 응답, 페이지, 로그, 주소에도 토큰이 없습니다.

**봉인의 한계.** 봉인 키는 `state/`와 같은 디스크의 `secrets.json`에 있습니다. 봉인은 `secrets.json` 없이 `state/`만 복사된 경우를 막을 뿐입니다. 내 파일을 읽을 수 있는 사람은 둘 다 읽을 수 있습니다. 다른 로컬 앱처럼 실제 보호는 파일 권한입니다.

## 로컬 API의 경계

StudyAI 자체 로그인은 없습니다. 대신 Worker가 요청마다 확인합니다(`worker/src/loopback.ts`).

- `Host` 헤더와 URL 호스트가 정확히 `127.0.0.1:<포트>`여야 합니다. 다른 이름으로 같은 포트에 닿는 DNS 리바인딩은 421로 거절합니다.
- `Sec-Fetch-Site`가 있으면 `same-origin`이어야 하고, `Origin`이 있으면 정확히 `http://127.0.0.1:<포트>`여야 합니다. 다른 사이트와 같은 컴퓨터의 다른 포트(`same-site`)는 403입니다.
- POST에는 `Origin`이 있어야 하고 본문은 JSON이어야 합니다. 다른 사이트의 폼이나 단순 요청은 이 형식을 보낼 수 없습니다.
- `STUDYAI_LOOPBACK`이 없는 서버는 `/api/health`를 빼고 모든 API를 Durable Object에 닿기 전에 "내 컴퓨터에서만" 안내로 거절합니다.

남는 한계: 같은 컴퓨터의 다른 운영체제 사용자나 프로그램은 이 포트에 연결할 수 있습니다. 여러 사람이 쓰는 컴퓨터에서는 StudyAI를 실행해 둔 채로 두지 마세요.

경로: `GET /api/health`, `GET /api/status`, `GET /api/chatgpt/models`, `POST /api/chatgpt/start`, `POST /api/chatgpt/disconnect`, `POST /api/chatgpt/resume`, `POST /api/chatgpt/model`, `POST /api/ai/ask`, `GET /auth/callback`. 실패 응답은 모두 `{ ok: false, code, message }`이고 `message`는 한국어 문장 하나입니다.

## 로그인 과정

1. **시작.** 설정이 `/api/chatgpt/start`를 보냅니다. 위 경계를 통과해야 합니다.
2. **동의.** 같은 탭이 OpenAI 승인 페이지로 갑니다. 새 등록이면 `agent_name_hint=StudyAI`가 붙고, PKCE, `state`, `nonce`를 씁니다.
3. **돌아오기.** OpenAI가 `http://127.0.0.1:<포트>/auth/callback`으로 돌려보냅니다. 이 경로는 다른 사이트에서 넘어오는 이동이므로 Origin 검사 대신 GET, 정확한 호스트, 대기 중인 시도 하나와 일치하는 `state`만 받습니다. 시도는 네트워크 요청 전에 소모되고, 모르는 `state`는 아무것도 바꾸지 않습니다. Worker는 코드를 교환하고 ID 토큰의 서명을 OpenAI 공개 키로, 그리고 발급자, 대상, 만료, nonce와 받은 권한 범위를 확인합니다. 이어지는 페이지는 고정 문장 하나와 설정으로 돌아가는 링크 하나만 보여 주며 주소의 내용을 되풀이하지 않습니다.
4. **설정으로 돌아오면** 새 상태를 읽습니다.

실패하거나 중간에 그만둔 로그인은 동작 중인 연결을 바꾸지 않습니다. **다른 ChatGPT 계정 사용**은 새 클라이언트를 등록하고, 새 연결이 검증되기 전까지 지금 연결을 유지합니다. OpenAI가 플랜 권한 없이 로그인을 허용하면 "플랜 사용 꺼짐"으로 기록하고 토큰은 저장하지 않습니다. **ChatGPT 플랜 사용 허용**은 동의를 다시 요청합니다.

## 동시성

Durable Object는 await 사이에 한 번에 한 호출만 실행합니다. await 전에 읽은 값에 기대는 쓰기는 동기 구간에서 식별자를 다시 확인합니다.

- **로그인 의도.** 새로 시작하거나 연결을 해제하면, 봉인이나 검증 중이던 이전 시도는 대기 행, 등록, 토큰, 알림을 더는 쓸 수 없습니다.
- **토큰 리비전.** 저장된 토큰 묶음마다 리비전이 있고 쓸 때마다 바뀝니다. 갱신, 401 재확인, 세션 종료는 저장된 리비전이 읽었던 그대로일 때만 동작합니다. 그래서 오래된 401이 새 토큰을 쓰거나 지우지 않습니다. 갱신은 리비전마다 하나만 진행하며 자체 마감 시간이 있어서, 요청 하나가 취소되어도 이미 OpenAI 쪽에서 회전한 갱신을 버리지 않습니다.
- **만료.** 만료된 접근 토큰은 항상 갱신합니다. `earliest_refresh_at`은 지금 토큰이 아직 쓸 수 있을 때만 갱신을 미룹니다.

`tests/chatgpt.account.test.ts`가 가짜 OpenAI로 이 경우들을 모두 실행합니다.

## 사용: 한도, 비용, 실패

- **달러 계산 없음.** ChatGPT 답에는 비용 값이 없습니다. StudyAI는 답마다 "ChatGPT 플랜 사용"을 보여 주고 비용을 세지 않습니다. 플랜 사용 한도는 같은 계정을 쓰는 모든 앱이 함께 씁니다. ChatGPT에서 확인하세요.
- **한도에 닿으면 멈춥니다.** 사용 한도나 자격 없음 답을 받으면 **다시 시작**을 누를 때까지 멈춥니다. 요청을 혼자 다시 보내지 않습니다.
- **실패는 정해진 문장으로.** 실패마다 한국어 문장 하나와 HTTP 상태 하나가 한 표(`src/core/chatgpt/messages.ts`)에 있습니다. OpenAI가 보낸 글은 응답에 넣지 않습니다.
- **마감 시간.** Worker는 요청 하나에 토큰 확인 전부터 170초, 헤더 30초, 무응답 60초를 줍니다. 브라우저는 180초를 기다리므로 Worker가 항상 먼저 답합니다. 연결 해제나 교체는 진행 중인 요청을 멈춥니다.
- **요청 형식.** 공개 Responses API를 `store: false`, `stream: true`로 부르고 `temperature`나 `max_output_tokens`는 보내지 않습니다. `response.completed`만 답으로 칩니다. 중간에 끝난 답(`response.incomplete`)은 잘린 답으로 보여 주지 않고 실패로 돌려줍니다.

## 연결 해제와 해지

**연결 해제**는 먼저 로컬 토큰을 한 번에 지우므로 어떤 경합에서도 해제가 이깁니다. 그다음 OpenAI에서 갱신 토큰을 해지하며 몇 번 다시 시도합니다. 설정은 해지가 확인됐는지 알려 줍니다. 등록은 남겨 두어 다음 로그인에서 같은 클라이언트를 씁니다. **저장된 계정 정보 지우기**는 등록까지 지웁니다.

**같은 클라이언트의 해지 (의도한 추정 기반 선택).** OpenAI는 로그아웃 때 갱신 토큰을 해지하라고 안내하지만, 갱신 토큰 하나를 해지하면 같은 클라이언트의 다른 권한도 끝나는지는 밝히지 않습니다. 끝난다면, 다시 로그인으로 방금 바뀐 토큰을 해지할 때 새 세션까지 끊깁니다. 그래서 StudyAI는 같은 클라이언트의 살아 있는 세션이 없을 때만 해지합니다. 다시 로그인으로 바뀐 같은 클라이언트의 토큰, 경합에서 진 갱신이 남긴 토큰은 메모리에서 버립니다. 저장, 기록, 응답하지 않으며 스스로 만료됩니다. 형제 세션 해지 여부는 확인되지 않았습니다.

## 확인된 것과 확인하지 않은 것

자동 테스트로 확인 (가짜 OpenAI 발급자 사용, 실제 OpenAI 계정이나 요청 없음, 브라우저 테스트는 루프백 HTTP):

- `tests/chatgpt.oauth.test.ts`, `tests/chatgpt.responses.test.ts`: 프로토콜.
- `tests/chatgpt.account.test.ts`: 위의 모든 경합, 해지 정책, 플랜 사용 꺼짐, 마감 시간, 멈춤, 모델, 저장 행 이름.
- `tests/worker.app.test.ts`: 경로, 루프백 경계(호스트, Origin, Fetch Metadata), 원격 사본 거절, 한국어 응답, 401 없음.
- `tests/local-launcher.test.ts`: 실행기. 이전 버전의 `secrets.json`으로 진짜 Worker를 띄워 봉인 키를 그대로 쓰는지, 파일이 바이트 단위로 그대로인지, 터미널 닫기(SIGHUP)가 잠금을 푸는지 확인합니다.
- `tests/e2e/worker-api.spec.ts`: workerd 안의 진짜 Worker와 Durable Object에 요청을 보내 연결, 튜터·생성·채점·점검 답, 사용 한도 멈춤과 다시 시작, 모델 선택, 연결 해제와 해지, DNS 리바인딩과 다른 출처 요청 거절을 확인합니다.
- `tests/e2e/worker-chatgpt.spec.ts`, `tests/e2e/worker-ui.spec.ts`: Chrome 안의 진짜 앱으로 같은 흐름을 확인합니다. 가짜 발급자는 앱(`127.0.0.1`)과 다른 사이트인 `localhost`에서 돌아서, 돌아오는 이동이 다른 사이트에서 옵니다. 한국어 화면에서 연결부터 학습 요청과 연결 해제까지 검사합니다.
- `tests/e2e/gate-hosted.spec.ts`: 변수 없는 운영 설정이 학습 앱을 그대로 보여 주고 모든 AI 경로를 거절하는지 확인합니다.

**실제로 확인하지 않은 것.** 만료에 따른 갱신, 해지, 같은 클라이언트 다시 로그인, 권한 거절, Safari는 실제 계정으로 확인하지 않았습니다. 가짜로 앱 쪽 경로는 확인했지만 OpenAI 쪽 동작은 모두 확인할 수 없습니다.

## 실제 계정으로 한 번 해 볼 것

기대기 전에 내 계정으로 한 번 해 보세요.

1. `pnpm local`, 설정 → AI → **ChatGPT로 계속하기**. OpenAI 페이지에 StudyAI 이름이 나와야 합니다.
2. 튜터에게 질문합니다. 답에 "ChatGPT 플랜 사용"이 보이고, 설정에 내 이메일과 계정의 모델이 보여야 합니다.
3. 접근 토큰 만료 시간이 지난 뒤(또는 다시 시작하고 기다린 뒤) 다시 묻고 갱신이 되는지 확인합니다.
4. **다시 로그인과 연결 해제.** **다시 로그인**(같은 클라이언트)을 마치고 다시 묻습니다. 새 세션이 동작하는지 확인한 뒤 연결을 해제하고 해지가 확인됐다고 나오는지 봅니다. 형제 세션 해지는 이것으로 확인되지 않습니다.
5. 플랜 권한을 한 번 거절합니다. 설정에 "플랜 사용 꺼짐"이 나오고 **ChatGPT 플랜 사용 허용**이 동의 화면을 다시 띄워야 합니다.
6. 터미널 출력에 `code=`나 `state=`가 없는지 봅니다. 실행기는 `wrangler dev --log-level warn`으로 돌며, wrangler 4.149에서는 이 단계에서 요청 줄이 나오지 않았습니다.
7. 선택: Safari에서 `http://127.0.0.1`로 연결이 되는지 확인합니다. 자동 확인은 Chrome뿐입니다.

## 인터넷에 올린 사본

인터넷에 올린 사본에서는 ChatGPT를 쓸 수 없습니다. `STUDYAI_LOOPBACK`이 정확히 `127.0.0.1:<포트>`가 아니면 모든 AI 경로가 404(`local-only`)이고, 돌아오기 경로도 없습니다. 이 값은 실행기만 씁니다. 학습 기능은 그대로 동작합니다.

이유와 열린 질문:

- OpenAI가 이 흐름에 안내하는 돌아오기 주소는 루프백 주소입니다. 원격 Worker에는 그런 주소가 없습니다.
- OpenAI는 원격 호스팅 앱의 플랜 사용을 제한적(대기 목록)으로 설명합니다. 원격 StudyAI나 로컬 도우미와 짝지은 구조가 플랜을 써도 되는지는 정해지지 않았습니다. 계정 코드는 동기 저장소만 받고 Cloudflare를 가져오지 않으므로 나중에 짝짓기 경로를 붙일 수 있지만, 지금은 없습니다.

## 그 밖의 열린 질문

- `earliest_refresh_at`의 단위는 문서에 없습니다. 숫자는 초로, ISO 문자열은 날짜로 읽고, 밀리초처럼 보이는 값은 무시합니다. 만료된 토큰은 그와 상관없이 갱신합니다.
- OpenAI가 갱신 토큰을 회전한 직후, StudyAI가 새 토큰을 저장하기 전에 프로세스가 멈출 수 있습니다. 그러면 다음 갱신이 재사용으로 실패하고 설정이 새 로그인을 요청합니다. OpenAI 쪽 지원 없이는 막을 수 없습니다.
